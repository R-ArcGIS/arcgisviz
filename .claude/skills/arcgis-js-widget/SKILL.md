# arcgisChart htmlwidget

Full architecture and data flow: `docs/js-widget-architecture.md` - read
that first for the complete picture. This skill is the quick-reference for
day-to-day changes.

## The one thing to know before touching anything

`inst/htmlwidgets/arcgisChart.js` and `arcgisChart.css` are **generated
output**, not source. The source is `srcjs/widgets/arcgisChart.js`. If you
edit the generated files directly, your changes are silently lost the next
time someone bundles.

## Build commands

This project uses `just` as the command-runner interface for everything
(R fmt/lint/test too, see `justfile`) - use the recipes, not raw `bun`
calls:

```sh
just js-install  # sync node_modules from package.json + bun.lock
just bundle-dev  # webpack --config webpack.dev.js (source maps, fast iteration)
just bundle      # webpack --config webpack.prod.js (minified - what ships)
just watch       # webpack --config webpack.dev.js -d --watch
```

Always `just bundle` (or at least `bundle-dev`) after editing
`srcjs/widgets/arcgisChart.js`, before testing the R side - `load_all()`
does not rebuild JS for you. `just --list` shows every recipe.

**Do not run `packer::scaffold_widget()` or any other `packer` R
function here.** `packer`'s own install/bundle helpers are hardcoded to
shell out to `npm` or `yarn`; this project uses `bun` (wrapped by `just`),
and there was already a real `bun.lock` with installed dependencies before
this scaffold existed. `packer` is not an installed dependency of this
project - the `srcjs/config/*.json` + `webpack.common/dev/prod.js` layout
was copied from packer's templates by hand (see
`docs/js-widget-architecture.md` for why), not generated by packer itself.
If you want packer's actual conventions for something new (e.g. a second
widget), fetch its templates
(`gh api repos/JohnCoene/packer/contents/inst/...`) rather than installing
and running the package.

## Adding a new widget entry point

1. Add `"widgetName": "./srcjs/widgets/widgetName.js"` to
   `srcjs/config/entry_points.json`.
2. Write `srcjs/widgets/widgetName.js` (see `arcgisChart.js` for the
   `HTMLWidgets.widget({ name, type: "output", factory })` shape).
3. Add `inst/htmlwidgets/widgetName.yaml` (dependency declaration - name/
   version/src/script/stylesheet, mirrors `arcgisChart.yaml`).
4. Write the R wrapper (`htmlwidgets::createWidget()` + Shiny
   Output/Render boilerplate) - mirror `R/arcgis-chart-widget.R`.
5. `just bundle`, then verify per "Verifying a change" below. Add the new
   widget's R file to `DESCRIPTION`'s `Collate:` if it has cross-file
   dependencies on other `R/` files.

No webpack config changes needed - `webpack.common.js` reads entry points
from the JSON file.

## The `createModel`/`<arcgis-chart>` contract

`<arcgis-chart>` takes a live `layer` (a `FeatureLayer` instance) and
`model` (a `BarChartModel`/etc. instance) as *properties*, not a plain
JSON config. `createModel({ iLayer, chartType })` (from
`@arcgis/charts-components`) builds the `FeatureLayer` internally from the
JSON `iLayer` you pass it (no live service needed for a
`type: "featureCollection"` layer) - get it back with `model.getLayer()`
to hand to `<arcgis-chart>`. Don't try to construct a `FeatureLayer`
yourself from the `iLayer` JSON; `createModel` already does it and
`model.getLayer()` is the documented way to retrieve it.

`chartType` values come from `@arcgis/charts-components`' `ModelTypes`
(`model/interfaces/common.d.ts`): `"barChart"`, `"lineChart"`,
`"comboBarLineChart"`, `"boxPlot"`, `"pieChart"`, `"scatterplot"`,
`"histogram"`, `"gauge"`, `"radarChart"`, `"heatChart"`. These are
deliberately different strings from the config-level series `type`
discriminators (e.g. `WebChartBarChartSeries.type = "barSeries"`) - don't
confuse the two when wiring a new chart type through.

## Verifying a change (no browser available here)

There's no browser automation in this environment. The verification
ceiling is:

```r
library(S7); library(s7x); library(arcgisutils)
devtools::load_all(quiet = TRUE)
df <- data.frame(x = c("a","b"), y = c(1, 2))
lyr <- arcgisutils::as_layer(df, name = "test", title = "Test")
w <- arcgis_chart(i_layer = lyr, chart_type = "barChart", x_field = "x", y_field = "y")
out <- tempfile(fileext = ".html")
htmlwidgets::saveWidget(w, out, selfcontained = FALSE)
# then grep the output for the expected <script>/<link> tags and the
# embedded x payload - see docs/js-widget-architecture.md for what a
# correct output looks like.
```

This confirms the R -> JSON -> htmlwidget dependency-resolution pipeline
end-to-end, and that webpack produced valid, loadable JS. It does **not**
confirm the chart actually renders correctly in a browser - that still
needs a human (or a real browser session) to check.
